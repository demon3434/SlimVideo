# 📱 《SlimVideo / 胶卷瘦身》Android 客户端开发设计文档

## 一、 项目概述

### 1.1 背景与痛点

当前 Android 智能手机录制视频的码率极高，导致录制的 MP4 视频文件极大（1GB 视频通常仅能录制数分钟的 4K 画面），极大压榨了用户的手机存储空间。

### 1.2 项目核心意图

本软件旨在开发一款纯 Android 手机本地运行的**无感视频瘦身工具**。在**完全不改变原视频目录、完全不修改原视频文件名**的前提下，在本地利用硬件加速精简视频体积，直接原位覆盖替换原视频，并智能同步系统相册，帮用户安全、快捷地释放手机空间。

---

## 二、 需求分析 (Requirement Analysis)

### 2.1 核心功能需求

1. **视频扫描与导入**：支持读取手机系统相册，获取视频路径。
2. **原片属性智能检测**：导入视频时，App 自动解析源视频的分辨率、总时长和当前码率。
3. **分档压缩预设（无感标签化）**：为不懂参数的用户提供情景化标签。
4. **动态体积预算**：用户勾选不同档位时，界面实时动态显示预估压缩后的文件尺寸。
5. **智能防呆拦截**：若源视频画质本身就低于某高档位预设，该高档位自动变灰（不可选），防止视频反向膨胀。
6. **原地覆盖与相册同步**：压缩完成后，自动删除大体积原文件，将新文件移至同目录并改为同名，同时触发 `MediaStore` 刷新相册。

### 2.2 非功能需求

1. **续航低消耗**：必须采用硬件加速方案，严禁长时间高负载卡死 CPU。
2. **后台高保活**：必须支持后台离线静默压缩，不因用户切出 App 导致任务崩溃。

### 3.2 动态体积估算数学模型

App 内部核心换算公式如下（音频统一采用复制模式，预估分配码率系数为 $192\text{ kbps}$）：

$$\text{预估文件大小 (MB)} = \frac{(\text{视频目标码率 kbps} + 192) \times \text{视频时长 (秒)}}{8 \times 1024}$$

* **日常高清档**：$\text{大小 (MB)} = \text{时长 (秒)} \times 0.573$
* **极致省空间档**：$\text{大小 (MB)} = \text{时长 (秒)} \times 0.268$
* **标清便携档**：$\text{大小 (MB)} = \text{时长 (秒)} \times 0.170$
* **极限留存档**：$\text{大小 (MB)} = \text{时长 (秒)} \times 0.096$

## 四、 软件架构设计 (Software Architecture)

本项目采用现代 Android 推荐的 **MVVM (Model-View-ViewModel)** 架构，结合 Jetpack 核心组件，确保代码松耦合、高性能。

```
 ┌────────────────────────────────────────────────────────┐
 │                      View (UI 层)                      │
 │       Jetpack Compose / Activity (参数选择与列表)       │
 └───────────────────────────┬────────────────────────────┘
                             │ 双向数据绑定 (State/Flow)
 ┌───────────────────────────▼────────────────────────────┐
 │                   ViewModel (业务逻辑层)                │
 │    读取视频属性 ──► 计算动态尺寸 ──► 触发后台任务调度     │
 └───────────────────────────┬────────────────────────────┘
                             │ 提交后台异步持久任务
 ┌───────────────────────────▼────────────────────────────┐
 │                 Repository & Background                │
 │   WorkManager (保活) ──► MediaCodec (硬件加速) ──► 覆盖   │
 └────────────────────────────────────────────────────────┘

```

## 五、 关键技术路线与代码实现要点

### 5.1 续航救星：MediaCodec 硬件加速

项目放弃使用耗电极大的纯 CPU 软件转码（如 FFmpeg 软解），全面采用手机内置的专用硬编解码芯片（ASIC）。

* **技术实现**：配置 `MediaFormat` 格式，硬编 H.265。
* **码率控制**：采用 **VBR（可变码率模式）**，代码配置如下：
```kotlin
mediaFormat.setInteger(MediaFormat.KEY_BITRATE_MODE, MediaCodecInfo.EncoderCapabilities.BITRATE_MODE_VBR)
mediaFormat.setInteger(MediaFormat.KEY_BITRATE, targetBitrate)

```


* **硬件兜底策略**：若极个别老旧手机没有 H.265 (HEVC) 硬件编码器，App 必须具备自动向下降级为 H.264 (AVC) 编码的能力，防止程序崩溃。

### 5.2 后台保活与抗杀死：Jetpack WorkManager

由于大视频转码即使走硬解也需要 1~2 分钟，为防止系统在后台将 App 杀死，必须将压缩业务封装在 `WorkManager` 中。

* **约束条件**：可配置 `Constraints`，如“仅在手机充电且连接 Wi-Fi 时”或“设备空闲时”在后台静默排队压缩。

### 5.3 核心“神操作”：原位同名覆盖逻辑

Android 分区存储（Scoped Storage）限制极严，覆盖原视频必须按以下安全步骤执行：

1. **产生临时文件**：将视频压缩并输出到 App 专有的沙盒缓存目录（Cache 目录），命名为 `temp_compressed.mp4`。
2. **文件校验**：转码成功后，校验新文件是否完好。
3. **向系统申请权限**：使用 `MediaStore.createDeleteRequest` 弹窗向用户申请删除原始大视频文件。
4. **原位原子替换**：原视频删除的瞬间，立即将 `temp_compressed.mp4` 移动至原视频路径下，修改名称为原文件名。
5. **通知媒体库**：调用 `MediaScannerConnection.scanFile()` 强制刷新系统媒体库，防止相册出现缩略图损坏或无法播放的物理异常。

## 六、 图标兼容性与全设备适配规范

项目已在 `icons/` 目录下准备好了一个高质量的正方形 PNG 原始图标。为确保在低版本 Android（有严重切角、强制切圆角的旧系统）以及现代旗舰机（高分辨率自适应图标）上均完美显示，将采用 **Android Studio Image Asset** 工具进行自动化矩阵生成。

### 6.1 高版本旗舰机适配：自适应图标 (Adaptive Icons)

Android 8.0 及以上系统会将图标拆分为前景和背景两层。

* **配置方式**：
* **背景层**：可直接在代码中使用标准科技蓝（`#1A73E8`）作为单色背景。
* **前景层**：将准备好的高分辨率 PNG 图标居中放置。


* **绝对安全区 (Safe Zone)**：自适应图标完全体逻辑尺寸为 $108 \times 108\text{ dp}$。在生成时，必须确保你的图标核心视觉元素（胶卷及箭头主体）收缩在**正中心直径为 $66\text{ dp}$ 的绝对安全圆圈之内**。这样可以确保无论华为、小米或三星系统如何魔改遮罩（切成圆形、泪滴形或方形），核心图案都绝对不会被切角。

### 6.2 低版本老旧机型兼容：传统图标 (Legacy Icons)

针对 Android 7.1 及以下不支持自适应图标的设备，系统会直接读取 `mipmap` 文件夹下的单层图片。
利用编译工具，将 `icons/` 目录下的原图按比例向各像素文件夹缩放分发：

| 目标 mipmap 文件夹 | 缩放像素尺寸 (px) | 适用屏幕密度与旗舰机兼容位置 |
| --- | --- | --- |
| `mipmap-mdpi` | $48 \times 48$ | 早期极低端机型 |
| `mipmap-hdpi` | $72 \times 72$ | 早期中端机型 |
| `mipmap-xhdpi` | $96 \times 96$ | 早期主流高清屏 |
| `mipmap-xxhdpi` | $144 \times 144$ | 现代中端机兼容档 |
| `mipmap-xxxhdpi` | $\mathbf{192 \times 192}$ | **当下顶级 2K/4K 屏幕旗舰机传统兼容最高档** |

> **⚠️ 传统图防切边贴士**：在缩放生成这些单层 PNG 时，软件已在四周自动留出了 **10%~15% 的透明内边距（Padding）**，确保旧版系统在强行切圆角时，应用边缘不会发虚或被蹭掉。

## 七、 项目开发里程碑规划

* **Phase 1**：搭建基础 MVVM 骨架，集成 `MediaMetadataRetriever` 读取本地视频。
* **Phase 2**：跑通 `MediaCodec` 硬件加速转码核心逻辑，实现 H.265 编码输出。
* **Phase 3**：编写前端参数选择界面，实现变灰拦截逻辑与动态体积计算公式绑定。
* **Phase 4**：攻克存储权限，实现沙盒转码后原位同名替换及 `MediaScanner` 刷新。
* **Phase 5**：使用 Image Asset 导入原图，完成全分辨率图标矩阵自动打包测试。
